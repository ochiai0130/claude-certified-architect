> 配点比率 / Weight: **16%**

- 評価データセットの構築・本番分布との整合・鮮度管理 / Building evaluation sets, matching the production distribution, keeping them fresh

- オフライン評価・オンライン評価・A/B テスト・統計的判断 / Offline and online evaluation, A/B testing, statistical decision-making
- CI での回帰検出・リリース判定・モデル更新時の比較 / Regression detection in CI, release gating, comparison across model upgrades
- 本番でのドリフト検知・人手レビューの標本設計・インシデントの評価への還流 / Production drift detection, human-review sampling, feeding incidents back into evaluation

## 問題 1 / Question 1

**シナリオ / Scenario:**

保険金請求の自動判定システムの評価データセットを構築します。担当者は「代表的なケース」として、社内で議論になった難しい事例を中心に 200 件を選びました。このデータセットでの精度は 68% でしたが、本番投入後の実測精度は 94% でした。逆に、本番で実際に問題を起こした事例の多くは、データセットに含まれていない類型（記入不備、添付漏れ、重複請求）でした。

An evaluation set for automated insurance-claim adjudication was built by selecting 200 "representative" cases, mostly difficult ones that had been debated internally. Measured accuracy on that set was 68%, while production accuracy turned out to be 94%. Conversely, most real production failures fell into categories absent from the set: incomplete forms, missing attachments, duplicate claims.

**設問 / Question:**

最も適切な改善はどれですか？

Which improvement is most appropriate?

- A) データセットを難しい事例だけに絞り込み、より厳しく評価する / Narrow the set to only hard cases for a stricter evaluation
- B) データセットの件数を 200 件から 2,000 件に増やす / Expand the set from 200 to 2,000 cases
- C) **本番の入力分布を反映したデータセットに再構築する**。実際の請求から層化抽出し、各類型（正常、記入不備、添付漏れ、重複請求など）が本番での出現比率に応じて含まれるようにする。難しい事例は「困難ケース」として別のスイートに分け、全体精度とは別に追跡する。本番で問題を起こした事例は必ずデータセットに追加する / **Rebuild the set to reflect the production input distribution**: stratify-sample from real claims so each category (clean, incomplete, missing attachment, duplicate, …) appears at its production frequency, keep the hard cases as a separate "difficult" suite tracked apart from overall accuracy, and always add production failures to the set
- D) 本番の実測精度が 94% なので、評価データセットは不要と判断する / Conclude that the evaluation set is unnecessary, since production accuracy is 94%

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: C**

**解説 / Explanation:**

評価データセットの価値は、**本番で起きることを予測できるか**で決まります。難しい事例に偏ったセットは、全体精度を過小評価すると同時に、本番で実際に多い類型（記入不備など）を全く測っていません。層化抽出で本番分布を再現すれば、全体精度が意味を持つ数字になります。同時に、困難ケースは別スイートとして残す価値があり、平均に埋もれさせずに追跡できます。**本番の失敗を必ずデータセットに戻す**運用が、同じ失敗の再発を防ぎます。

An evaluation set is worth what it predicts about production. A hard-case-skewed set both understates aggregate accuracy and fails to measure the categories that actually dominate production. Stratified sampling makes the aggregate number meaningful, while keeping hard cases as a separate suite preserves that signal instead of burying it in an average — and feeding production failures back is what stops recurrence.

- **A 不正解**: 偏りをさらに強めるだけで、本番の主要な失敗類型は依然として測定されません。 / Deepens the skew and still measures none of the real failure categories.
- **B 不正解**: 同じ偏った基準で 10 倍に増やしても、分布の偏りは是正されません。 / Ten times the same bias is still biased.
- **D 不正解**: 本番精度は事後的な指標で、変更前に品質を予測する手段がなくなります。回帰検出もできません。 / Production accuracy is retrospective; without an evaluation set, changes cannot be assessed before shipping.

**参照 / Reference:** 評価データセットの分布整合、層化抽出、困難ケースの分離
</details>

## 問題 2 / Question 2

**シナリオ / Scenario:**

生成された顧客向け回答の品質を、Claude を評価者（LLM-as-judge）として自動採点しています。評価者には「回答 A と回答 B のどちらが優れているか」を判定させています。監査したところ、(1) 提示順が先の回答が選ばれる割合が 61%、(2) 同一のモデルが生成した回答が、別のモデルの回答より高く評価される傾向、(3) 長い回答が短い回答より高く評価される傾向、が確認されました。

Generated customer responses are auto-scored using Claude as a judge, asked "which of response A or B is better?" An audit found: (1) the first-presented response wins 61% of the time, (2) responses generated by the same model as the judge score higher than another model's, and (3) longer responses score higher than shorter ones.

**設問 / Question:**

最も適切な改善はどれですか？

Which improvement is most appropriate?

- A) **判定の偏りを構造的に打ち消す設計にする**。提示順を入れ替えた 2 回の判定を行い、順序を変えても同じ結論になった場合のみ採用する。評価基準を「どちらが優れているか」という漠然とした問いから、具体的な観点（正確性・網羅性・簡潔性）ごとの明示的なルーブリックに変える。判定結果は人手ラベルのサブセットと突き合わせて校正し、偏りの残存を継続測定する / **Structurally cancel the biases**: judge each pair twice with the order swapped and accept only order-consistent verdicts, replace the vague "which is better" with an explicit rubric scoring specific dimensions (accuracy, completeness, concision), and calibrate the judge against a human-labeled subset, continuing to measure residual bias
- B) 評価者のプロンプトに「順序や長さに影響されないこと」と明記する / Instruct the judge not to be influenced by order or length
- C) 評価者を軽量モデルに変更してコストを下げる / Switch the judge to a lighter model to reduce cost
- D) LLM-as-judge をやめて、全件を人手で評価する / Abandon LLM judging and evaluate everything by hand

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: A**

**解説 / Explanation:**

LLM-as-judge には既知の系統的な偏り（**位置バイアス、自己選好バイアス、冗長性バイアス**）があり、指示で消せるものではありません。位置バイアスは順序を入れ替えた二重判定で構造的に打ち消せます。冗長性バイアスは、漠然とした優劣判断を具体的なルーブリック採点に変えることで軽減されます。そして最も重要なのは、**評価者そのものを人手ラベルで校正する**ことです。評価システムも評価される対象であるという認識が要点です。

LLM judges carry known systematic biases — position, self-preference, verbosity — that instructions do not remove. Position bias is cancelled structurally by swapped-order double judging; verbosity bias is reduced by replacing a vague preference with rubric-scored dimensions. Most importantly, the judge itself must be calibrated against human labels: the evaluator is also a system under evaluation.

- **B 不正解**: 指示による偏りの抑制は効果が限定的で、測定された 61% という系統的偏りを解消する根拠がありません。 / Instructions do not remove a measured systematic bias.
- **C 不正解**: 評価者を弱くすると判定品質が下がり、偏りは残ったままです。コストは評価の妥当性より優先されません。 / Weakens judgment while leaving the biases intact.
- **D 不正解**: 全件人手は規模的に成立せず、人手評価にも一貫性の問題があります。校正用のサブセットに限定するのが実務的です。 / Does not scale, and human labels have their own consistency issues; use them for calibration.

**参照 / Reference:** LLM-as-judge、位置バイアス、自己選好バイアス、ルーブリック採点、評価者の校正
</details>

## 問題 3 / Question 3

**シナリオ / Scenario:**

新しいエージェント構成をリリースするにあたり、オフライン評価データセット（1,200 件）で旧構成より 6 ポイント優れていることを確認しました。チームは「オフライン評価で十分な差が出たので、そのまま全面リリースしてよい」と考えています。この構成では、エージェントがツールを呼ぶ順序と回数が変わっており、実運用ではツールの応答時間や一時的な障害の影響を受けます。

Before releasing a new agent configuration, offline evaluation on 1,200 items shows it 6 points better than the current one. The team believes this justifies a full release. The new configuration changes the order and number of tool calls, and in production it will be subject to tool latency and transient failures.

**設問 / Question:**

最も適切な判断はどれですか？

Which judgment is most appropriate?

- A) オフライン評価で 6 ポイント優れているので、全面リリースしてよい / A 6-point offline gain justifies a full release
- B) オフライン評価の件数を 5,000 件に増やしてから全面リリースする / Expand offline evaluation to 5,000 items, then release fully
- C) オフライン評価をやめて、本番で直接測定する / Skip offline evaluation and measure directly in production
- D) **オフライン評価は必要条件だが十分条件ではないと判断し、オンライン評価を組み合わせる**。オフラインでは測れない要素（ツールの実応答時間、一時障害時の挙動、実ユーザーの入力分布、レイテンシとコストの変化）を本番で測る必要があるため、カナリアで段階的に比率を上げながら、品質指標に加えて運用指標も監視する。後退条件を事前に定義する / **Treat offline evaluation as necessary but not sufficient and add online evaluation**: real tool latency, behavior under transient failures, the real user input distribution, and changes in latency and cost cannot be measured offline, so canary at increasing traffic share while monitoring operational metrics alongside quality — with rollback criteria defined in advance

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: D**

**解説 / Explanation:**

オフライン評価は**入力と出力の対応を安価に大量に測れる**点で不可欠ですが、実環境の要素（ツールの実応答時間、一時障害、実ユーザーの入力分布、レイテンシ・コスト）を含みません。ツール呼び出しの順序と回数が変わる構成では、これらの影響がとりわけ大きくなります。オフラインとオンラインは代替関係ではなく補完関係にあり、両方を通すのが正しい判断です。後退条件の事前定義が、カナリアを実効的にします。

Offline evaluation is indispensable for measuring input-output quality cheaply at volume, but it excludes real tool latency, transient failures, the true input distribution, and cost. A change that alters tool-call order and count is precisely where those matter most. Offline and online are complementary, not alternatives, and pre-defined rollback criteria are what make the canary real.

- **A 不正解**: オフラインで測れない運用面の劣化（レイテンシ増、障害時の挙動）を見ずにリリースする判断です。 / Ships without measuring the operational dimensions the change most affects.
- **B 不正解**: 件数を増やしてもオフライン評価の性質は変わらず、測れない要素は測れないままです。 / More items do not add the missing dimensions.
- **C 不正解**: オフライン評価を捨てると、明らかな品質劣化を本番前に捕捉する安価な手段を失います。 / Discards the cheap pre-production safety net.

**参照 / Reference:** オフライン評価とオンライン評価の役割、カナリア、後退条件
</details>

## 問題 4 / Question 4

**シナリオ / Scenario:**

固定の評価データセット 800 件を基準に、6 か月間プロンプトを繰り返し改善してきました。当初 74% だった精度は 93% まで向上しています。しかし、本番での実測品質は同期間でほとんど改善しておらず、むしろ一部の指標は悪化しています。プロンプトの改善は、評価セットで誤答した事例を個別に分析して指示を追加する形で進めてきました。

Over six months, prompts have been iterated against a fixed 800-item evaluation set, raising accuracy from 74% to 93%. Production quality, however, has barely improved over the same period and some metrics have declined. Each iteration analyzed the set's failures individually and added instructions for them.

**設問 / Question:**

最も適切な診断と対応はどれですか？

Which diagnosis and response is most appropriate?

- A) 本番の測定方法に問題があるので、本番の指標を評価セットに合わせて再定義する / The production measurement is wrong; redefine production metrics to match the evaluation set
- B) **評価セットへの過適合が起きていると診断する**。同じ 800 件に対して繰り返し調整した結果、そのセット固有の事例に最適化され、汎化していない。対応として、調整に使わない**ホールドアウトセット**を分離し、定期的に新しい本番データからセットを更新する。ホールドアウトでの精度が改善していなければ、その変更は本物の改善ではないと判断する / **Diagnose overfitting to the evaluation set**: six months of tuning against the same 800 items has optimized for those specific cases rather than generalizing. Separate a **holdout set** never used for tuning, refresh the sets periodically from new production data, and treat any change that does not improve holdout accuracy as not a real improvement
- C) プロンプトの改善を止め、現状のまま運用する / Stop iterating on prompts and freeze the current version
- D) 評価セットを 800 件から 8,000 件に増やす / Expand the evaluation set from 800 to 8,000 items

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: B**

**解説 / Explanation:**

**同じデータセットに対して繰り返し最適化すると、そのセットに過適合します。**評価セットの精度と本番品質が乖離しているという観察は、過適合の典型的な兆候です。対策の中心は**ホールドアウトセットの分離**で、調整に一度も使っていないデータでの性能が汎化の指標になります。加えて、セットを定期的に本番データから更新することで、リークの蓄積を防ぎます。「評価セットで良くなった」を「良くなった」と読み替えないことが要点です。

Repeatedly optimizing against one dataset overfits it, and a widening gap between set accuracy and production quality is the classic symptom. The core remedy is a holdout never used for tuning, whose performance measures generalization, plus periodic refresh from production data to stop leakage from accumulating. The discipline is refusing to read "better on the eval set" as "better."

- **A 不正解**: 本番の指標を評価セットに合わせるのは、実態ではなく測定を歪める対応です。因果が逆転しています。 / Bends the measurement to fit the artifact rather than the reality.
- **C 不正解**: 改善を止めても過適合したプロンプトが残るだけで、汎化の問題は解決しません。 / Freezes the overfitted state without addressing generalization.
- **D 不正解**: 件数を増やしても、その 8,000 件に対して同じ手法で調整すれば同じ過適合が起きます。ホールドアウトの分離が本質です。 / The same procedure overfits 8,000 items too; the holdout is what matters.

**参照 / Reference:** 評価セットへの過適合、ホールドアウトセット、データセットの更新
</details>

## 問題 5 / Question 5

**シナリオ / Scenario:**

不正取引の一次スクリーニングを Claude で行います。検出された取引は人間の調査員が精査します。取引の 0.3% が実際の不正で、調査員の処理能力は 1 日 300 件です（1 日の取引は 12 万件）。現在の構成は「精度（accuracy）」を最大化するようチューニングされ、accuracy は 99.6% ですが、実際の不正の 45% を見逃しています。

Claude performs first-pass screening for fraudulent transactions; flagged items go to human investigators. 0.3% of transactions are truly fraudulent, investigators can process 300 items/day, and there are 120,000 transactions/day. The system is tuned to maximize accuracy, reaching 99.6%, but misses 45% of actual fraud.

**設問 / Question:**

最も適切な指標設計はどれですか？

Which metric design is most appropriate?

- A) accuracy をさらに高めるようチューニングする / Tune for even higher accuracy
- B) 検出された全件を自動的に不正として処理する / Automatically treat every flagged item as fraud
- C) **accuracy を主要指標から外し、再現率（recall）を主指標、調査員の処理能力を制約条件とする設計に変える**。0.3% という不均衡データでは、全件を「正常」と判定するだけで accuracy 99.7% になるため指標として機能しない。「1 日 300 件以内という制約のもとで再現率を最大化する」という定式化にし、適合率は調査員の負荷として管理する / **Drop accuracy as the primary metric: make recall primary with investigator capacity as a constraint.** At 0.3% prevalence, labeling everything "clean" already yields 99.7% accuracy, so the metric carries no information. Formulate the objective as maximizing recall subject to flagging at most 300 items/day, and manage precision as investigator workload
- D) 不正の定義を変えて、検出しやすい類型のみを対象にする / Redefine fraud to cover only easily detected patterns

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: C**

**解説 / Explanation:**

**不均衡データにおいて accuracy は指標として無意味**です。0.3% の不正率では、何も検出しないシステムでも accuracy 99.7% を達成します。この用途では**見逃しのコスト（不正の実害）が誤検知のコスト（調査員の工数）より圧倒的に大きい**ため、再現率が主指標になります。同時に、調査員の処理能力（1 日 300 件）は動かせない制約なので、「制約下での再現率最大化」という定式化が実務に即しています。指標は業務のコスト構造から導くものです。

Accuracy is meaningless under class imbalance: at 0.3% prevalence, flagging nothing scores 99.7%. Here the cost of a miss (realized fraud) vastly exceeds the cost of a false positive (investigator time), so recall is primary — subject to the hard constraint of 300 reviews per day. Metrics are derived from the business cost structure, not chosen by convention.

- **A 不正解**: accuracy の追求が見逃し 45% という現状を生んでいます。指標そのものが誤っています。 / Pursuing accuracy is what produced the 45% miss rate.
- **B 不正解**: 人間の精査を飛ばすと誤検知が顧客に直接影響し、正当な取引を止めることになります。 / Removes the human check, hitting legitimate customers directly.
- **D 不正解**: 検出しやすいものだけを不正と定義するのは、指標を良く見せるために問題を再定義する行為です。 / Redefines the problem to flatter the metric.

**参照 / Reference:** 不均衡データにおける指標選択、再現率と適合率、制約付き最適化
</details>

## 問題 6 / Question 6

**シナリオ / Scenario:**

2 つのプロンプト候補を比較しています。評価セット 120 件で、候補 A は 88 件正解、候補 B は 93 件正解でした。チームは「B が 4 ポイント優れているので B を採用する」と判断しようとしています。過去にも同様の判断で採用したプロンプトが、本番で改善を示さなかったことが数回ありました。

Two prompt candidates are being compared. On a 120-item evaluation set, candidate A scores 88 correct and candidate B scores 93. The team is about to adopt B on the grounds that it is 4 points better. On several past occasions, prompts adopted this way showed no improvement in production.

**設問 / Question:**

最も適切な判断はどれですか？

Which judgment is most appropriate?

- A) 4 ポイント差は明確なので、B を採用する / A 4-point gap is clear; adopt B
- B) **この差が偶然の範囲かを検定し、必要なサンプル数を見積もる**。120 件で 5 件の差は統計的に有意とは限らず、同じ手続きを繰り返せば偶然でこの程度の差は生じ得る。検出したい効果量に対して必要な件数を事前に見積もり、評価セットを拡充するか、差が小さい場合は「実質的に同等」と判断して他の基準（コスト、レイテンシ、保守性）で選ぶ / **Test whether the gap is within chance and size the sample properly.** A 5-item difference on 120 is not necessarily significant, and repeating this procedure will produce gaps of this size by chance. Estimate the sample size needed for the effect you want to detect, expand the set accordingly, or — if the difference is small — declare them effectively equivalent and choose on other grounds (cost, latency, maintainability)
- C) 評価セットを変えて再測定し、B が勝った方を採用する / Re-measure on a different set and adopt whichever wins
- D) 両方を本番に出して、苦情が少ない方を残す / Ship both and keep the one with fewer complaints

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: B**

**解説 / Explanation:**

**小さな評価セットでの小さな差は、偶然と区別できません。**120 件で 5 件の差は、統計的にはノイズの範囲に収まる可能性が十分にあります。「過去に同様の判断が本番で再現しなかった」という観察は、まさにこの現象の症状です。正しい手続きは、検出したい効果量から必要件数を事前に見積もることで、これにより「差がないことも結論できる」評価になります。差が実質的に無い場合、コストや保守性で選ぶのは合理的な判断です。

Small differences on small sets are indistinguishable from noise; 5 of 120 can easily be chance, and the team's history of non-reproducing gains is that phenomenon's symptom. The correct procedure sizes the sample from the effect you want to detect, which also lets you conclude *equivalence*. When two candidates are effectively equal, choosing on cost or maintainability is sound.

- **A 不正解**: 統計的裏付けのない判断で、過去に再現しなかった経緯を無視しています。 / Ignores both statistics and the team's own track record.
- **C 不正解**: 勝つまで測り直すのは、偶然の勝利を採用する手続きです（多重検定の問題）。 / Re-measuring until one wins selects for chance.
- **D 不正解**: 苦情は感度が低く遅い指標で、比較の対照条件も統制されていません。 / Complaints are a slow, low-sensitivity, uncontrolled signal.

**参照 / Reference:** 統計的有意性、サンプルサイズ設計、実質的同等性の判断
</details>

## 問題 7 / Question 7

**シナリオ / Scenario:**

- **D 不正解**: 最大の領域だけを見るのは、小さいが重要な領域の劣化を見落とす選択です。 / Examines the segment least likely to be hiding the problem.

**参照 / Reference:** セグメント別評価、集計値による劣化の隠蔽、重要領域の独立基準
</details>

## 問題 26 / Question 26

**シナリオ / Scenario:**

LLM-as-judge に使うモデルを新しいバージョンに更新しました。更新後、被評価システムには一切変更を加えていないにもかかわらず、評価スコアが平均 5 ポイント上昇しました。チームは「システムが改善した」と報告しようとしています。過去 8 か月分のスコア推移グラフには、この更新時点で明確な段差が生じています。

The judge model used for LLM-as-judge was upgraded. With no change whatsoever to the system under evaluation, average scores rose by 5 points. The team is about to report this as an improvement. The eight-month score trend shows a clear discontinuity at the upgrade point.

**設問 / Question:**

最も適切な対応はどれですか？

Which response is most appropriate?

- A) 新しい評価者の方が正確なので、5 ポイントの上昇を改善として報告する / Report the 5 points as improvement, since the new judge is more accurate
- B) 評価者の更新を取り消して旧バージョンに戻す / Roll the judge back to the previous version
- C) **評価者の変更はスコアの断絶を生むと認識し、比較可能性を回復させる**。被評価システムが変わっていない以上、5 ポイントは評価者の変化であってシステムの改善ではない。新旧の評価者で同一のサンプルを採点して差を定量化し、必要なら過去のスコアを再採点して系列の一貫性を回復する。あわせて、評価者を人手ラベルに対して校正し直し、以後は評価者のバージョンも変更管理の対象として記録する / **Recognize that changing the judge breaks score comparability, and restore it.** With the system unchanged, the 5 points are a judge change, not an improvement. Quantify the shift by scoring the same sample with both judge versions, re-score historical items where continuity matters, recalibrate the judge against human labels, and from now on treat the judge's version as a managed, recorded change
- D) 評価スコアの絶対値は見ず、相対比較のみに使う / Ignore absolute scores and use the judge only for relative comparison

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: C**

**解説 / Explanation:**

**評価システムそのものが変わると、時系列の比較可能性が失われます。**被評価対象が不変なのにスコアが動いた以上、それは測定器の変化です。これを改善として報告するのは事実に反します。正しい対応は、新旧評価者で同一サンプルを採点して差を定量化し、系列の一貫性を回復することです。**評価者のバージョンを変更管理の対象にする**という運用上の教訓も重要で、これがないと同じ混乱が繰り返されます。評価基盤は、それ自体が管理すべき本番システムです。

Changing the measuring instrument breaks the time series. With the measured system unchanged, the shift is instrument drift, and reporting it as improvement is simply false. Quantify the offset by dual-scoring the same sample, restore continuity, recalibrate against human labels — and treat the judge's version as managed configuration, or the confusion recurs. The evaluation stack is itself a production system.

- **A 不正解**: 被評価システムが不変なのだから、システムの改善ではありません。事実に反する報告になります。 / The measured system did not change; reporting improvement is false.
- **B 不正解**: 旧バージョンに戻せば断絶は避けられますが、評価者の改善（もしあれば）も捨て、いずれ同じ問題に直面します。 / Avoids the discontinuity by forgoing the upgrade and merely defers the problem.
- **D 不正解**: 相対比較だけでも、評価者が変わった前後をまたぐ比較は依然として無効です。問題は解決しません。 / Relative comparisons across a judge change are equally invalid.

**参照 / Reference:** 評価者のバージョン管理、スコアの比較可能性、評価基盤の変更管理
</details>

## 問題 27 / Question 27

**シナリオ / Scenario:**

3 か月前、本番で「特定の書式の請求書で金額を 10 倍に誤読する」という重大な不具合が発生し、修正しました。今週、別の変更をリリースしたところ、同じ不具合が再発し、再び顧客に影響が出ました。前回の修正時、原因分析と修正は行いましたが、その事例を評価スイートには追加していませんでした。

Three months ago, a serious defect — misreading amounts as 10× on a particular invoice format — occurred in production and was fixed. This week, an unrelated change shipped and the same defect recurred, affecting customers again. The original fix included root-cause analysis but the case was never added to the evaluation suite.

**設問 / Question:**

最も適切な再発防止策はどれですか？

Which is the most appropriate prevention measure?

- A) 修正時のコードレビューをより厳格にする / Make code review at fix time more rigorous
- B) **インシデントを評価ケースに変換する手順を、修正プロセスの必須ステップにする**。本番で発生した不具合は、原因分析と修正に加えて、その事象を再現する評価ケースをスイートに追加することを完了条件とする。追加されたケースは以後すべての変更で自動実行され、同じ回帰が二度本番に到達しない。既知の過去インシデントについても遡って追加する / **Make converting an incident into an evaluation case a mandatory step of the fix process**: a production defect is not "done" until a case reproducing it exists in the suite. That case then runs on every subsequent change, so the same regression cannot reach production twice — and add cases retroactively for known past incidents
- C) 請求書の書式ごとに担当者を割り当てて目視確認する / Assign a person per invoice format to check visually
- D) 変更のリリース頻度を下げる / Reduce release frequency

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: B**

**解説 / Explanation:**

**同じ不具合が二度起きたという事実は、修正プロセスに「再発防止の仕組み化」が欠けていることを示しています。**原因を直しても、それを検証し続ける手段がなければ、無関係な変更で容易に壊れます。インシデントを評価ケースに変換することを修正の完了条件にすれば、対策が個人の記憶ではなく自動実行される仕組みとして残ります。過去のインシデントを遡って追加することで、この 3 か月間に蓄積した他の再発リスクも同時に塞げます。

A defect recurring is evidence that the fix process lacks a mechanism for preventing recurrence: fixing the cause without a continuing check leaves it easy to break with an unrelated change. Making the evaluation case a completion criterion converts the lesson from individual memory into an automatically enforced one, and back-filling past incidents closes the other latent recurrences accumulated meanwhile.

- **A 不正解**: レビューの厳格化は人的注意に依存し、無関係な変更が引き起こす回帰は発見しにくいです。 / Depends on human attention and is poor at catching regressions from unrelated changes.
- **C 不正解**: 目視確認は網羅性がなくスケールせず、書式が増えるたびに人員が必要になります。 / Unscalable and non-exhaustive.
- **D 不正解**: 頻度を下げても、変更あたりの回帰リスクは変わりません。検出手段がないことが原因です。 / The cause is missing detection, not release cadence.

**参照 / Reference:** インシデントの評価への還流、回帰スイートの成長、修正の完了条件
</details>

## 問題 28 / Question 28

**シナリオ / Scenario:**

エージェントの品質指標として「LLM-as-judge による回答スコア」を採用し、6 か月にわたってこの指標を改善してきました（72 → 88）。しかし同期間で、事業側の指標（一次解決率、エスカレーション率、顧客満足度）はいずれも改善していません。経営層から「品質指標が上がっているのに事業成果が出ないのはなぜか」と問われています。

Over six months, the team improved its quality metric — an LLM-judge response score — from 72 to 88. Over the same period, business metrics (first-contact resolution, escalation rate, customer satisfaction) did not improve. Leadership asks why business outcomes have not followed the quality metric.

**設問 / Question:**

最も適切な対応はどれですか？

Which response is most appropriate?

- A) **指標そのものの妥当性を検証する**。品質指標が事業成果と相関しているかを実データで確認し、相関がなければその指標は最適化対象として不適切である。個別の事例で高スコアだが解決に至らなかったものを分析し、判定基準が事業上重要な要素（実際に問題を解決したか、必要な行動を促したか）を捉えているかを見直す。必要なら指標を事業成果に近い代理指標に置き換える / **Validate the metric itself.** Check empirically whether the quality score correlates with business outcomes; if it does not, it is the wrong thing to optimize. Analyze cases that scored highly yet did not resolve the customer's problem, and re-examine whether the rubric captures what matters commercially — whether the issue was actually resolved, whether the necessary action was prompted — replacing the metric with a closer proxy for the outcome if needed
- B) 事業側の指標の測定方法に問題があると判断する / Conclude that the business metrics are measured incorrectly
- C) 品質指標をさらに改善して 95 を目指す / Push the quality metric further, toward 95
- D) 品質指標の改善実績をもって成果として報告する / Report the metric improvement as the achievement

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: A**

**解説 / Explanation:**

**代理指標を長期に最適化すると、その指標が事業成果から乖離することがあります。**16 ポイントの改善が事業指標に全く反映されていないという観察は、指標の妥当性そのものを疑うべき強い証拠です。検証の方法は、高スコアなのに解決に至らなかった事例を分析することで、ここから「判定基準が何を見落としているか」が具体的に分かります。指標は目的ではなく手段であり、目的との相関が失われたら指標を変えるのが正しい対応です。

Optimizing a proxy for long enough can decouple it from the outcome, and a 16-point gain with no business movement is strong evidence that has happened. The diagnostic is analyzing high-scoring cases that failed to resolve, which shows concretely what the rubric misses. A metric is a means; when its correlation with the end is gone, the metric changes.

- **B 不正解**: 3 つの独立した事業指標が揃って動いていない状況で、まず疑うべきは品質指標の妥当性です。 / With three independent business metrics flat, the quality proxy is the likelier suspect.
- **C 不正解**: 事業成果と相関しない指標をさらに追求しても、乖離が広がるだけです。 / Widens the gap between proxy and purpose.
- **D 不正解**: 事業成果に結びつかない指標の改善を成果として報告するのは、問いに答えていません。 / Does not answer the question that was asked.

**参照 / Reference:** 代理指標の妥当性、指標と事業成果の相関検証、指標の見直し
</details>

## 問題 29 / Question 29

**シナリオ / Scenario:**

LLM-as-judge による自動評価を導入して 1 年が経ちました。導入時には人手ラベル 400 件との一致率が 89% であることを確認していますが、それ以降、評価者の妥当性は検証していません。この 1 年で、被評価システムの出力スタイルは大きく変わり（構造化された箇条書き中心に）、扱う業務領域も 2 つ増えました。自動評価のスコアは安定して高い水準を示しています。

Automated LLM-judge evaluation has been in place for a year. At introduction, agreement with 400 human labels was 89%; the judge's validity has not been checked since. Over that year, the system's output style changed substantially (now mostly structured bullet lists) and two new business areas were added. Automated scores have remained stably high.

**設問 / Question:**

最も適切な対応はどれですか？

Which response is most appropriate?

- A) 導入時に 89% の一致率を確認しているので、追加の検証は不要 / No further validation is needed given the 89% at introduction
- B) 自動評価をやめて人手評価に戻す / Abandon automated evaluation and return to human review
- C) **評価者の妥当性を定期的に再検証する仕組みを導入する**。出力スタイルと業務領域が変わった以上、1 年前の一致率は現在の妥当性を保証しない。定期的に人手ラベルのサンプルと突き合わせて一致率を測り、特に新しく追加された業務領域と、変化した出力形式について個別に確認する。一致率が閾値を下回った場合はルーブリックまたは評価者の見直しを行う / **Institute periodic revalidation of the judge.** With output style and coverage both changed, a year-old agreement figure does not establish current validity. Re-measure agreement against fresh human labels on a schedule, checking the two new business areas and the changed output format specifically, and revise the rubric or the judge when agreement falls below a threshold
- D) 自動評価のスコアが安定しているので、妥当性も保たれていると判断する / Take the stability of the scores as evidence that validity holds

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: C**

**解説 / Explanation:**

**評価者の妥当性は、評価対象が変われば変わり得ます。**出力スタイルが箇条書き中心に変わり、業務領域が 2 つ増えたということは、1 年前に校正した条件がもはや成立していないということです。特に新しい業務領域は、評価者が一度も人手ラベルと突き合わされていない領域です。定期的な再校正を仕組みとして持つことで、評価基盤の信頼性を維持できます。**評価するものも評価される**という原則が本問の核心です。

A judge's validity is relative to what it evaluates, and both the output style and the coverage have changed since calibration. The two new areas in particular have never been checked against human labels at all. Scheduled recalibration keeps the evaluation stack trustworthy — the evaluator is itself subject to evaluation.

- **A 不正解**: 評価対象が変わった以上、過去の一致率は現在の妥当性の根拠になりません。 / Past agreement does not carry over to a changed target.
- **B 不正解**: 全面的な人手評価はスケールせず、自動評価の利点を捨てています。必要なのは校正であって撤退ではありません。 / Recalibration is needed, not retreat.
- **D 不正解**: スコアの安定性は妥当性の証拠になりません。一貫して誤った評価も安定して見えます。 / Consistently wrong scoring is also stable.

## 問題 30 / Question 30

**シナリオ / Scenario:**

対話型サポートエージェントの品質を継続的に把握したいと考えています。人手評価は月 1 回・200 件が限界で、明示的なユーザー評価（星評価）の回答率は 6% です。一方、システムには「同じユーザーが同じ問題について再質問した」「人間のオペレーターにエスカレーションされた」「会話が途中で放棄された」「提示された手順の後に成功イベントが記録された」といった行動データが全トラフィックについて蓄積されています。

You want continuous visibility into an interactive support agent's quality. Human review is capped at 200 items/month and explicit star ratings have a 6% response rate. Meanwhile, the system records behavioral data across 100% of traffic: the same user re-asking about the same issue, escalation to a human operator, conversation abandonment, and success events recorded after the agent's suggested steps.

**設問 / Question:**

最も適切な品質監視の設計はどれですか？

Which quality-monitoring design is most appropriate?

- A) 人手評価の件数を月 200 件から 400 件に増やす / Double human review to 400 items/month
- B) 星評価の回答率を上げるため、評価を必須にする / Make star ratings mandatory to raise the response rate
- C) 明示的な星評価のみを品質指標として使う / Use the explicit star ratings alone as the quality metric
- D) **全トラフィックで観測できる行動指標を主要な継続監視指標とし、人手評価と組み合わせる**。再質問率・エスカレーション率・放棄率・後続の成功イベント率を継続的に追跡し、これらが品質の代理として妥当かを人手評価のサンプルと突き合わせて検証する。行動指標は全件で取れるため異常検知に適し、人手評価は代理指標の校正と原因分析に使う。星評価は回答者に偏りがあることを前提に補助的に扱う / **Make behavioral metrics observable on 100% of traffic the primary continuous signal, combined with human review**: track re-ask rate, escalation rate, abandonment rate, and downstream success rate, and validate them as quality proxies against the human-reviewed sample. Behavioral signals cover everything and suit anomaly detection; human review calibrates the proxies and explains causes; star ratings are treated as supplementary given respondent bias

<details>
<summary>正解と解説 / Answer & Explanation</summary>

**正解 / Answer: D**

**解説 / Explanation:**

継続監視には**全トラフィックで観測できる指標**が必要です。人手評価は精度が高いが被覆率が極めて低く（月 200 件）、明示的評価は回答率 6% で回答者に偏りがあります。一方、再質問・エスカレーション・放棄・後続の成功は全件で観測でき、いずれも品質と直接的な関係を持ちます。要点は、**行動指標を代理として使う妥当性を人手評価で検証する**ことで、これにより「代理指標が本当に品質を反映しているか」が担保されます。3 種類の信号をそれぞれの強みに応じて使い分ける設計です。

Continuous monitoring needs signals available on all traffic. Human review is accurate but covers 200 items a month; explicit ratings reach 6% with respondent bias. Re-asks, escalations, abandonment, and downstream success are observable universally and relate directly to quality. The essential step is validating those proxies against the human-reviewed sample, so each of the three signals is used for what it is good at.

- **A 不正解**: 2 倍にしても被覆率は依然として極めて低く、継続監視の役割は果たせません。 / Still negligible coverage for continuous monitoring.
- **B 不正解**: 評価を必須にするとユーザー体験を損ない、義務的な回答は品質信号としての価値も低くなります。 / Harms UX and yields low-value coerced responses.
- **C 不正解**: 回答率 6% の自己選択的なサンプルは、母集団を代表しません。 / A self-selected 6% is not representative.

**参照 / Reference:** 行動指標による継続監視、代理指標の校正、信号の使い分け
</details>
